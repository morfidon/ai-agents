# Find Next Improvement Agent

## Goal

Use spare AI capacity for one worthwhile repository investigation. Rank up to three candidates by estimated percentage fit and run the best one.

## Method

- Read project instructions and the README. Sample the current diff or a recent change, nearby tests, and one important entry point.
- Identify up to three distinct, evidence-backed candidates. Keep each scoped to one workflow or module and its direct dependencies.
- Score eligible candidates using the rubric. Open and follow the first-ranked agent. If its instructions are unavailable, report that limitation and carry out a bounded read-only review of the selected candidate.

## What to Look For

| Signal | Agent |
| --- | --- |
| Flags, retries, resets, or callbacks control one lifecycle | [State Machine Review](2.state-machine-review-agent.md) |
| A common task crosses a UI, API, CLI, or MCP interface | [Experience Walkthrough](3.experience-walkthrough-agent.md) |
| Repeated rules drift or a module is hard to change safely | [Codebase Maintenance](4.codebase-maintenance-agent.md) |
| Project evidence points to a product gap | [Feature Exploration](5.feature-exploration-agent.md) |
| A specific invariant can be tested in a finite model | [Formal Verification](6.formal-verification-agent.md) |
| The user requests an authorized, defensive source review | [Security Review](7.security-review-agent.md) |

## Scoring

Score each dimension from 0 to 5. Use 0 for unsupported, 3 for adequate, and 5 for strong. Use intermediate values between those anchors.

| Dimension | Weight | What to check |
| --- | --- | --- |
| Evidence | 40% | A concrete signal in the project supports this investigation. |
| Impact | 30% | The result could improve an important workflow or inform a real decision. |
| Budget fit | 20% | The scope fits the requested effort and the available tools. |
| Actionability | 10% | The result can point to a specific fix, check, or decision. |

Fit (%) = 8 × Evidence + 6 × Impact + 4 × Budget fit + 2 × Actionability. Break ties by stronger evidence, then smaller scope. Rank only candidates with project evidence.

## Expected Output Format

```text
1. State Machine Review — 88% (selected)
   Scope: round restart
   Evidence: game/round.gd:54 arms a timer owned outside the round.
2. Codebase Maintenance — 70%
   Scope: save-slot validation
   Evidence: storage/save.gd:27 and ui/slots.gd:103 repeat the same range check.

Selected investigation:
<Use the selected agent's output format here.>
```

## Output Rules

- Show the fit percentage, scope, and one evidence reference per candidate. Use Severity and Confidence for findings as defined by the selected agent.
- Keep the project read-only. Honor the requested effort and use any extra budget to deepen the selected investigation.
- Treat fit as an estimate and avoid quoting a token balance the host does not expose.
- When no candidate has enough evidence, report what you checked and stop.
