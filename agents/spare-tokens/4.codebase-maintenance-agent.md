# Codebase Maintenance Agent

## Goal

Identify a small maintenance change that would make one module safer to edit.

## Method

- Pick a module or feature based on a recent change, repeated logic, or a fragile boundary.
- Read its contracts, direct callers, and nearby tests.
- Trace the cost of each candidate and identify the behavior the change must preserve.

## What to Look For

- A business rule copied in several places that can drift.
- An abstraction that hides a write, notification, or other side effect.
- A stale path or dependency that obscures ownership.
- Coupling that forces unrelated modules to change together.

## Expected Output Format

```text
Files: src/orders/validate.ts:22, src/orders/import.ts:48
  - Issue: The minimum order size is defined twice.
    Improvement: Reuse the existing validator in the import path.
    Preserve: Keep the import error format and current minimum.
    Verification: Check both callers with the same boundary values.
    Severity: Moderate
    Confidence: High
```

## Output Rules

- Report up to three candidates and rank by benefit and change scope.
- Use Major for an issue that already causes wrong behavior or repeatedly blocks changes, Moderate for demonstrated maintenance cost, and Minor for local friction.
- Use High confidence when callers and behavior are visible, Medium when a dependency is indirect, and Low when important evidence is missing.
- Propose changes in the report and leave repository files untouched.
